# フロアマップ作成アプリ 仕様書

最終更新：2026-10-28

## 1. 概要・目的

区画番号入りのフロア画像を読み込むだけで、クリックできる施設フロアマップを作成し、スマホで閲覧できるようにするWebアプリ。

- 対象施設は限定しない（学校、野外会場、オフィスビル、ホールのブース分けなど）
- 作成はPCブラウザ、閲覧はスマホ（QRコードまたはマップコードで開く）。対応端末はPC、iPhone、Android
- 個人開発のため、言語はTypeScriptに統一し、自前のサーバーを持たない構成にする
- 閲覧者の現在地表示とルート案内は対象外
- 画面と店舗情報は多言語（日本語・英語・中国語の簡体字・繁体字）に対応する

## 2. 利用者

| 利用者 | 主な端末 | やること |
| --- | --- | --- |
| 管理者（マップ作成者） | PCブラウザ | フロア画像と店舗情報を取り込み、マップを作成・修正・公開する |
| 閲覧者（来場者など） | スマホ | QRコードかマップコードでマップを開き、店舗を探して詳細を見る（ログイン不要） |

## 5. マップ自動作成（AI）の流れ

自動検出の結果は下書き。管理者が確認・修正して保存した時点で区画が確定する。

1. フロア画像をアップロード
2. 境界検出（OpenCV.js）：線を抽出し、閉じた領域を多角形にする
3. 番号読み取り（Gemini API）：区画番号と画像上の位置を取得（2と並行）
4. 番号の位置を含む多角形にその番号を割り当てる
5. 編集画面に下書きとして表示（読めなかった区画は「番号未設定」、書式違いは「要確認」）
6. 管理者が確認・修正して保存し、店舗情報と番号で紐づける

| 画像の種類 | 想定精度 | 対策 |
| --- | --- | --- |
| CAD図面 | 高い | そのまま検出。寸法線など不要な線の除外設定を用意 |
| パンフレットのスキャン | 中程度 | 傾き補正、色の除去、白黒化の前処理 |
| 手書き | 低い | 下書きの修正、または手動作成を前提にする |

AIを呼ぶのはマップ作成時と翻訳時だけ。閲覧時には呼ばない。

## 6. データ構造

「マップ → 建物 → フロア → 区画 → 店舗」の5階層。区画と店舗は1対1。

| テーブル | 主な項目 | 備考 |
| --- | --- | --- |
| profiles（管理者） | id、メールアドレス、メール確認済み、plan_id、停止状態 | ログインはSupabase Auth。メール確認前はマップ作成不可 |
| plans（プラン） | id、名前、マップ数上限、AI実行回数上限、画像容量上限、料金 | |
| usage（利用状況） | profile_id、AI実行回数、使用中の画像容量 | AI実行と画像アップロードのたびに更新 |
| maps（マップ） | id、名前、マップコード、owner_id、公開状態（private/public/limited）、公開開始日時、公開終了日時 | 本人以外は編集不可（RLS） |
| buildings（建物） | id、map_id、建物・エリアコード（A、B、Nなど）、表示名、表示順 | 建物が1つでも1件作る。野外はエリアとして登録 |
| floors（フロア） | id、building_id、階コード（1、10、B1など）、表示名、表示順、画像URL、画像の幅・高さ | 画像はSupabase Storage |
| sections（区画） | id、floor_id、区画番号、多角形の座標（JSON）、作成方法（manual/ai） | 座標は画像のピクセル基準。区画番号はマップ内で重複不可 |
| shops（店舗） | id、section_id、店名、genre_id、営業時間、紹介文、画像URL、SNSリンク（複数） | 日本語が基本データ |
| shop_translations（翻訳） | shop_id、言語（en / zh-Hans / zh-Hant）、店名、営業時間、紹介文、翻訳方法（ai/manual） | 翻訳がない項目は日本語を表示 |
| genres（ジャンル） | id、map_id、名前、表示色、各言語の名前 | マップ作成時に初期一覧を自動登録 |
| map_publications（公開版） | id、map_id、公開日時、マップ全体のデータ（JSON） | 「公開」操作時に下書き全体をまとめて保存。閲覧画面はこれだけを読む |

座標の例：`[[120,80],[260,80],[260,190],[120,190]]`（左上から時計回り）

### 区画番号の表記ルール

書式は「建物（エリア）コード-階コード＋区画の2桁連番」。1フロアの区画は99までを想定。合わない番号は取り込み時・入力時に警告する。

| ケース | 例 | 意味 |
| --- | --- | --- |
| 通常の階 | A-101 | A棟1階の区画1 |
| 10階以上 | A-1001 | A棟10階の区画1 |
| 地下階 | A-B101 | A棟地下1階の区画1 |
| 建物がない会場 | N-101 | 北エリアの区画1（階は1として扱う） |

### マップコード

マップ作成時に自動生成。英数字6桁程度で、O/0、I/1/Lなど紛らわしい文字は使わない（桁数は要調整）。大文字・小文字は区別しない。

### Excel取り込みの書式（案）

| 区画番号 | 店名 | ジャンル | 営業時間 | 紹介文 | 画像 | SNSリンク |
| --- | --- | --- | --- | --- | --- | --- |
| A-101 | （例）カフェ〇〇 | 飲食 | 10:00〜20:00 | 自家焙煎のコーヒー店 | cafe.jpg | https://instagram.com/… |

- 画像はファイル名を書き、画像ファイルをまとめてアップロードして照合する（取り込み後に個別登録も可）
- SNSリンクが複数ある場合は改行で区切る
- サンプル：`docs/test-data/shops_sample.xlsx`

### 初期ジャンル

飲食、物販、展示、体験・ワークショップ、サービス、施設（トイレ・案内所・休憩所）。自由に追加可能。

## 7. 動作の重さへの対策

- 閲覧画面では表示中のフロアのデータと画像だけを読み込む
- フロア画像はアップロード時に縮小・圧縮し、表示用と編集用の2サイズを保存する
- 縮小表示中は店名を省略し、拡大したときだけ表示する
- 区画が非常に多い場合にSVGからCanvas描画（Konvaなど）へ切り替えられるよう、描画部分を1つの部品にまとめる

| 項目 | 決定内容 |

| 対応端末 | PC、iPhone、Android |

## 9. 未決事項

### テスト版の結果を見て決める

- AI自動作成・翻訳の回数の数え方（1マップ／1フロア／アカウント合計、翻訳を店舗ごとに数えるか）
- 推奨する画像の条件（形式、最大サイズ、解像度）
- フロア画像の容量上限

### 公開までに決める

- 不正利用されたマップを止める方法（問題報告ボタン、運営者用の管理画面など）
- 有料プランの上限と料金
- 利用規約・プライバシーポリシー、特定商取引法に基づく表記
- データの保存期間と削除、プラン変更時の扱い、バックアップ
- サービス名とドメイン（QRコードのURLになるため公開後は変えにくい）
